## 1. 快速总结

### 1.1 一句话总结

本文借鉴 Karpathy AutoResearch，将量化选股研究拆解为可被 Agent 循环执行的策略协议、版本管理和样本隔离三层框架，使大模型能够在固定投资逻辑和严格数据边界内自动提出修改、运行回测、保留或回滚版本。

### 1.2 核心问题

文章研究的不是“LLM 能否直接预测股票”，而是：

1. 如何把研究员的策略逻辑写成 Agent 可执行协议；
2. 如何允许 Agent 探索，同时防止其任意改动研究目标；
3. 如何记录每次修改，使研究路径可回溯；
4. 如何隔离训练、验证和测试集，防止自动迭代污染最终结果；
5. Agent 的改进是否能够从验证集迁移至测试集。

### 1.3 核心框架

```text
SKILL.md：策略逻辑和操作纪律
skill_config.yaml：参数边界
skill_strategy_gen.py：读取版本并生成组合
skill_strategy_backtest.py：分段回测
version/：保存配置、权重和结果
        ↓
Agent 提出一个主要假设
        ↓
训练集生成与初筛
        ↓
验证集决定保留或回滚
        ↓
测试集仅用于最终复核
```

### 1.4 主要结果

报告首页和第 9 页显示，保留版本的测试集结果从初始版本到后期版本出现以下改善：

| 指标 | 初始版本 | 后期代表版本 |
| --- | ---: | ---: |
| 年化收益 | 13.47% | 15.67% |
| 年化波动 | 19.46% | 17.58% |
| 夏普比率 | 0.69 | 0.89 |
| 最大回撤 | 25.59% | 约 19.38% |
| 年化换手 | 10.66 | 8.70 |

该结果说明 Agent 不只是提高历史收益，也在部分版本中降低波动、换手和回撤。

### 1.5 核心评价

本文的行业价值在于把“研究经验”从自然语言说明提升为受约束、可版本化、可样本隔离的执行协议。其真正 Alpha 属于 Research Process Alpha 和 Organizational Alpha，而非某个价值成长因子。主要局限是实验仍由单一初始策略、单一市场和有限版本构成，且尚缺少与人工研究、随机搜索、贝叶斯优化和单 Agent 脚本的严格对照。

## 2. 研究背景：传统量化研究为何需要 Agent 化

量化研究通常在以下要素之间循环：

```text
投资假设
+
数据约束
+
因子与规则
+
组合约束
+
评价指标
        ↓
修改代码
        ↓
回测
        ↓
解释结果
        ↓
提出下一轮修改
```

传统流程存在四个问题：

1. **版本记录不完整**：研究员往往只保留最终结果，失败路径和修改原因丢失；
2. **修改归因不清晰**：多个参数同时变化，难判断收益提升来自哪里；
3. **研究过程受近期结果影响**：研究员容易围绕最近一次回测继续调参；
4. **经验难以复用**：策略逻辑、数据边界和操作纪律散落在代码、文档和个人记忆中。

研报第 3 页将 Karpathy AutoResearch 视为启发：把研究任务限制在固定时间预算和明确协议中，让 AI Agent 修改可控文件、运行实验、读取结果并决定保留或回滚。

与一般机器学习任务不同，量化策略具有明显的非平稳性。某次回测提升可能只是贴合某一阶段，因此 Agent 化的重点不应只是自动调参，而是：

- 固化研究假设；
- 约束修改边界；
- 保存逻辑路径；
- 隔离最终测试数据。

## 3. 主体架构：策略协议、版本管理与样本隔离

研报第 4 页用“温室中的树”说明三层结构：

| 层次 | 回答的问题 | 主要作用 |
| --- | --- | --- |
| 策略协议层 | 策略可以怎样变化 | 固定投资逻辑与可修改边界 |
| 版本管理层 | 每次变化如何记录和复盘 | 保存配置、持仓、评分和结果 |
| 样本隔离层 | 改进是否真实而非贴合历史 | 分离训练、验证和测试权限 |

三层不是并列装饰，而是共同决定 Skill 能否从说明文档升级为研究协议。

---

## 4. 策略协议层：把研究逻辑变成可执行边界

策略协议层应写清：

- 核心投资逻辑；
- 可使用的数据和因子；
- 因子方向；
- 股票池与流动性要求；
- 持仓数量和单票上限；
- 调仓频率；
- 交易成本；
- 允许修改的参数；
- 不允许修改的公共函数和评测口径。

研报以稳健低波价值优选策略为例，强调策略并非简单购买低估值股票，而是在具备基本盈利能力和可交易性的股票中，比较行业内估值安全边际，并加入质量、分红、成长稳定和风险控制。

### 4.1 Agent 自由度为何必须受限

若允许 Agent 任意修改：

- 股票池；
- 标签；
- 回测代码；
- 成交价格；
- 基准；
- 测试区间；

它很容易通过修改评测体系而非改进策略获得更好结果。

因此，Agent 默认不应修改：

- 已有策略代码的公共逻辑；
- 回测引擎；
- 数据分段；
- 评价函数。

每轮迭代只围绕一个主要假设展开，例如：

- 提高分红防守权重；
- 调整价值安全边际；
- 放宽或收紧流动性门槛；
- 优化持仓数量；
- 调整单票权重上限。

“一轮一个主假设”是提高归因能力的重要设计。

## 5. Skill 文件结构

研报第 5 页将研究信息分散到多个文件，使人类和 Agent 分别获得适合读取的接口。

| 文件或目录 | 作用 |
| --- | --- |
| `SKILL.md` | 描述策略逻辑、迭代纪律和禁止事项 |
| `skill_config.yaml` | 保存股票池、因子和参数边界 |
| `skill_strategy_gen.py` | 读取配置并生成组合 |
| `skill_strategy_backtest.py` | 分训练、验证、测试回测 |
| `result/skills/{skill_name}/v{version}/` | 保存每一版本的配置、权重、调仓日和结果 |

这种设计具有三个工程优点：

1. **关注点分离**：策略说明、参数配置和执行代码相互独立；
2. **版本可审计**：每个版本拥有完整上下文；
3. **Agent 权限可控**：只开放配置或特定策略模块，不开放评测系统。

### 5.1 Skill 与普通 Prompt 的区别

普通 Prompt 通常描述“做什么”，而 Skill 还规定：

- 哪些数据可用；
- 哪些参数可改；
- 如何评价；
- 什么情况下回滚；
- 如何保存版本；
- 测试集何时可访问。

因此 Skill 更接近研究治理协议，而不是提示词模板。

## 6. 样本隔离：防止自动研究逐步污染测试集

研报第 5 页给出的数据权限为：

| 样本 | 区间 | 权限 |
| --- | --- | --- |
| 训练集 | 2014-12-31 至 2018-12-28 | 用于策略生成和初步筛选 |
| 验证集 | 2018-12-28 至 2020-12-31 | 用于版本保留或回滚 |
| 测试集 | 2020-12-31 至 2026-04-30 | 不进入自动迭代，仅最终复核 |

其核心原则是：

> 只有策略在训练集和验证集上同时表现出较一致改善，才认为修改可能对应有效逻辑；测试集只用于最终检验，不能成为 Agent 的反馈信号。

### 6.1 为什么验证集也可能被过拟合

即使测试集不参与迭代，Agent 仍会反复观察验证结果。随着试验次数增加，验证集逐渐成为新的训练集。

因此更严格的框架应补充：

- 验证集查询预算；
- 多个滚动验证窗口；
- 对失败版本也完整记录；
- 最终一次性测试；
- 多市场或多个起止日期复核；
- 多重检验修正。

## 7. 初始策略：仅作为 Agent 工作流的实验载体

本节只讨论与 Agent 验证直接相关的策略设置，不将其扩展为独立因子研究。

## 7.1 可交易股票池

研报第 6 页先构建基础可选池：

- 全 A 股；
- 股票处于可交易状态；
- ROE 为正；
- 估值因子可得；
- 流通市值和成交额分位过滤极小市值和低流动性股票；
- 默认阈值约为 0.35 和 0.40，候选不足时适度放宽。

目的不是创造 Alpha，而是避免后续版本改进由不可交易小票驱动。

## 7.2 行业内价值安全边际

使用 `EP_TTM` 作为估值因子、`ROE_TTM` 作为盈利能力分组变量，在行业内回归估值与盈利关系，并寻找同等盈利能力下估值更具吸引力的股票。

该设计减少简单低估值策略对周期、金融或低质量公司的机械偏好。

## 7.3 三组质量得分

初始策略包含三组得分：

- `leader`：使用 `ROIC_TTM` 和收入规模代理龙头质量；
- `dividend`：使用两年平均股息收益、股利价格比、经营现金流收益和 60 日波动率；
- `growth_stability`：使用净利润增速及增长稳定性。

三组大致等权，并与价值安全边际结合。

## 7.4 组合构建

- 月度调仓；
- 目标持有 30 只；
- 缓冲池 45 只；
- 单票权重上限 5%；
- 使用下行波动率倒数定权；
- 交易成本按双边约 3 bps 计入。

这些规则定义了 Agent 可优化但不能任意推翻的初始研究空间。

## 8. Agent 迭代与版本保留

一个完整循环应包含：

```text
读取当前 Skill 和版本结果
        ↓
提出单一可解释假设
        ↓
修改允许范围内的配置
        ↓
运行训练集与验证集回测
        ↓
比较收益、波动、回撤、换手和胜率
        ↓
保留或回滚
        ↓
记录修改原因与结果
```

### 8.1 版本保留不应只看收益

研报同时观察：

- 年化收益；
- 年化波动；
- 夏普比率；
- 最大回撤；
- Calmar；
- 换手率；
- 月度、季度、半年度和年度胜率。

这能避免 Agent 通过提高风险或换手获得表面收益提升。

### 8.2 从“复杂因子堆叠”转向“逻辑推进”

第 10 页的版本复盘显示，较有效的修改往往作用于：

- 红利与防守；
- 价值安全边际；
- 低波动控制；
- 持仓数量与权重上限；
- 流动性约束。

部分复杂因子替换或多方向同时修改未能稳定进入优选版本。

这说明自动研究的价值不在于无约束增加复杂度，而在于：

> 对一个逻辑假设进行可验证、可回滚的渐进修改。

## 9. 实验结果与可信度

## 9.1 测试集版本变化

研报第 9 页列出的代表结果为：

| 版本 | 年化收益 | 年化波动 | 夏普 | 最大回撤 | Calmar | 年化换手 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 初始版本 v0.0 | 13.47% | 19.46% | 0.69 | 25.59% | 0.53 | 10.66 |
| v0.19 | 13.63% | 17.21% | 0.79 | 18.01% | 0.75 | 9.22 |
| v0.25 | 14.53% | 17.79% | 0.82 | 18.20% | 0.80 | 9.42 |
| v0.27 | 15.67% | 17.58% | 0.89 | 19.38% | 0.81 | 8.70 |

可以看出：

- 收益并非单调上升；
- 某些中间版本回撤更低；
- 最终代表版本兼顾收益、波动与换手；
- 版本选择本身是多目标权衡，而不是寻找单一最高收益。

## 9.2 验证集与测试集关系

报告发现：

- 验证集夏普较高的版本，测试集往往也不差；
- 测试集改善幅度通常小于验证集；
- 验证集与测试集存在正相关，但并非强线性关系。

这支持验证集筛选具有一定外推价值，但也说明：

- 验证改善不能直接等同于真实 Alpha；
- 多轮查询仍会导致验证集过拟合；
- 最终需要滚动样本外和多任务复核。

## 10. Agent 系统的核心创新

## 10.1 将研究逻辑从说明文档升级为执行协议

Skill 同时约束投资逻辑、数据、参数、组合、评测和权限，使 Agent 不只是生成代码，而是在受治理环境中开展研究。

## 10.2 版本路径成为研究资产

每个版本保存：

- 修改假设；
- 配置；
- 持仓；
- 调仓日；
- 训练与验证结果；
- 是否保留。

这使失败实验也能形成“研究记忆”。

## 10.3 样本隔离成为 Agent 权限的一部分

测试集不是简单的技术划分，而是访问控制。Agent 无权使用测试集优化策略。

## 10.4 将自动研究目标从参数最优转为逻辑可解释

报告强调渐进式修改和复盘路径，降低复杂因子堆叠导致的不可归因。

---

## 11. Agent 研究的主要难点

### 11.1 自动化边界

开放过多权限会导致评测投机；限制过严又会退化为普通参数搜索。

### 11.2 评估函数决定 Agent 行为

若只奖励收益，Agent 可能提高风险、换手或小盘暴露。评价体系必须与真实投资目标一致。

### 11.3 验证集多次查询

Agent 的高实验频率会放大验证集过拟合，需要预算控制和多窗口复核。

### 11.4 结果归因

策略改善可能来自：

- 真实经济逻辑；
- 风格暴露；
- 特定行情；
- 降低仓位；
- 偶然参数。

必须有风险归因和消融分析。

### 11.5 可复现性

LLM 版本、温度、上下文、工具环境和随机性都会影响修改路径。必须保存：

- 模型版本；
- Prompt/Skill 版本；
- 工具调用；
- 随机种子；
- 完整日志；
- 数据快照。

### 11.6 研究成本

自动研究需要持续消耗：

- Token；
- 回测算力；
- 存储；
- 人工复核；
- 数据授权。

如果单次策略空间较简单，固定程序或传统优化算法可能更便宜。

## 12. 优点

- 主问题明确：自动化的是研究循环，而非直接预测；
- 三层治理框架清晰；
- Skill 文件结构具体；
- 样本权限划分严格；
- 版本保留和回滚机制完整；
- 评价指标不仅关注收益；
- 提供测试集结果和版本复盘；
- 强调逻辑推进而非复杂度堆叠。

---

## 13. 不足

### 13.1 缺少强基线

应比较：

- 人工研究员迭代；
- 随机搜索；
- 网格搜索；
- 贝叶斯优化；
- 遗传算法；
- 单 Agent 无 Skill；
- 仅配置搜索的固定脚本。

否则难以确认增量来自 LLM Agent，还是来自规范化实验流程。

### 13.2 单一任务验证不足

当前主要围绕稳健低波价值策略。若要证明通用性，应覆盖：

- 纯量价策略；
- 行业轮动；
- 事件驱动；
- 组合风险模型；
- 不同市场和不同数据频率。

### 13.3 测试集仍可能受到人工选择影响

即使 Agent 不访问测试集，研究者可能根据最终测试结果选择展示版本或修改 Skill。应预注册最终测试规则。

### 13.4 缺少运行成本与失败统计

报告主要展示保留版本，尚需披露：

- 总实验数；
- 失败和回滚比例；
- 平均 Token 成本；
- 平均回测时间；
- 人工干预次数；
- Agent 代码错误率。

### 13.5 版本路径未完全证明“自进化”

当前更接近受约束的自动实验与配置优化。若要称为自进化，还需证明 Skill 能够从跨任务经验中更新自身研究规则。

## 14. 可迁移 Alpha

## Alpha 1：Research Process Alpha

核心逻辑：在相同时间内完成更多受控实验，并保留完整研究轨迹。

价值来源：

- 提高实验覆盖；
- 降低重复劳动；
- 缩短假设验证周期。

失效风险：如果搜索空间低质量或评价函数错误，更快实验只会更快过拟合。

## Alpha 2：Decision Consistency Alpha

核心逻辑：Skill 固定数据边界、评价指标和操作纪律，减少研究员因近期回测结果改变标准。

价值来源：提高跨版本判断一致性。

## Alpha 3：Organizational Alpha

核心逻辑：将个人经验写成可复用、可审计的研究协议。

价值来源：

- 新研究员可快速接入；
- 失败经验不会丢失；
- 团队共享统一评测标准。

## Alpha 4：Validation Governance Alpha

核心逻辑：通过权限控制和版本预算，减少测试集污染与验证集反复查询。

价值来源：提高样本外结果可信度。

## Alpha 5：Search-Space Design Alpha

核心逻辑：优质 Skill 不是让 Agent 什么都能改，而是设计高质量可变空间。

价值来源：把研究资源集中在经济逻辑明确、可归因的方向。

## 16. 核心评价

本文最重要的贡献是把量化研究中的隐性操作纪律显式化：

```text
投资逻辑
+
可修改边界
+
版本路径
+
样本访问权限
+
统一评价
=
可执行研究协议
```

它展示了 Agent 在投研中的合理定位：不是替代预测模型，也不是任意生成策略，而是在受约束环境中执行研究循环。未来能否形成真正的组织级 Alpha，取决于是否具备严格基线、跨任务验证、成本统计、完整日志和验证集治理。
